# Часть 1. GA4

## Шаг 0. Убедиться, что вы в нужном свойстве

Открыть https://analytics.google.com/analytics/web/#/p548194448/admin

`Data collection and modification` → **Data streams**

**Ожидается:** ровно один поток, тип **Web**, домен notix-ai.app, идентификатор
**`G-KEQZHBGJKN`**.

**Если видите поток Android** — вы в свойстве приложения, вернитесь по ссылке выше.

Названия свойств задаются руками и ничего не гарантируют: «Notix Web» — это то,
как его назвали, а не признак того, что внутри. Проверяется именно по
measurement ID.

---

## Шаг 1. Custom dimensions — самое срочное

`Data display` → **Custom definitions** → вкладка Custom dimensions →
**Create custom dimension**

Создать два, по одному за раз:

| Dimension name | Scope | Event parameter |
|---|---|---|
| `Placement` | Event | `placement` |
| `Link URL` | Event | `link_url` |

**Зачем.** Сайт отправляет с каждым кликом по кнопке App Store два параметра:
откуда кликнули (`hero`, `nav`, `footer_cta`, `example`) и куда вёл линк. GA4 их
принимает и хранит, но **не показывает ни в одном отчёте**, пока измерение не
зарегистрировано. До этого видно только «кто-то кликнул» — без ответа на вопрос,
какая кнопка работает.

**Почему срочно.** Регистрация не действует задним числом. События, пришедшие до
неё, остаются без разреза навсегда.

**Ожидается:** в списке две строки со статусом Active.

**Частая ошибка:** GA4 не проверяет, приходил ли такой параметр вообще —
опечатка в поле Event parameter создастся без ошибки и просто всегда будет
пустой. Параметр пишется строчными: `placement`, не `Placement`.

**Когда появятся данные:** через 24–48 часов, задним числом не заполнятся.

---

## Шаг 2. Хранение данных — 14 месяцев

`Data collection and modification` → **Data retention**

Event data retention: переключить **2 months → 14 months**, Save.

**Зачем.** На значении по умолчанию через год не с чем будет сравнивать: детальные
данные просто удаляются. Агрегированные отчёты живут дольше, но любой разрез по
параметрам ограничен этим сроком — включая `placement` из шага 1.

**Ожидается:** после сохранения в поле стоит 14 months.

**Частая ошибка:** настройка отдельная в каждом свойстве. У приложения
(`530303000`) она тоже на двух месяцах, но это другая задача.

---

## Шаг 3. Проверить, что событие вообще приходит

Живая проверка, без неё следующий шаг сделать нельзя.

1. Открыть https://notix-ai.app в обычном окне
2. В баннере согласия нажать **Accept** — до этого аналитика не грузится вообще
3. Кликнуть любую кнопку App Store
4. В GA4: Reports → **Realtime**

**Ожидается:** в списке событий появляется `app_store_click` в течение полуминуты.

**Если не появилось:**
- проверьте, что нажали именно Accept, а не Decline — выбор запоминается, и
  переспрашивать баннер не будет; сбросить можно, удалив в localStorage ключ
  `notix.analytics.consent`, либо открыв приватное окно
- блокировщик рекламы режет googletagmanager.com — проверяйте в окне без него

---

## Шаг 4. Отметить конверсию

`Data display` → **Events** → найти строку `app_store_click` → тумблер
**Mark as key event**

**Зачем.** Без отметки событие не попадает в отчёты по конверсиям и не может быть
целью в рекламе — а реклама в App Store у нас в планах.

**Ожидается:** тумблер включён, событие появляется в разделе Key events.

**Частая ошибка:** строки в списке не будет, пока событие не пришло хотя бы раз.
Поэтому шаг 3 идёт раньше. Список обновляется с задержкой до суток.

---

## Шаг 5. Фильтр внутреннего трафика

Делается в два приёма, и второй обычно забывают.

**5а. Описать, что считать своим трафиком**

`Data collection and modification` → Data streams → выбрать поток →
**Configure tag settings** → Show all → **Define internal traffic** → Create

- Match type: IP address equals
- Value: ваш IP (посмотреть на любом сервисе вида «what is my ip»)

**5б. Включить фильтр**

`Data collection and modification` → **Data filters**

Фильтр `Internal Traffic` там уже есть — GA4 создаёт его сам. Он в состоянии
**Testing**, то есть **не фильтрует ничего**. Открыть → переключить в **Active** →
Save.

**Ожидается:** статус фильтра Active.

**Частая ошибка:** остановиться после 5а. Правило создано, фильтр в списке есть,
а свои визиты продолжают идти в отчёты — и на маленьком трафике искажают всё.

**Оговорка:** домашний IP у большинства провайдеров динамический. Если цифры
снова поедут — проверьте, не сменился ли адрес.

---

## Шаг 6. Google signals — оставить выключенным

`Data collection and modification` → **Google signals**

Ничего не включать, просто убедиться, что выключено.

**Зачем.** Включение добавляет демографию, но привязывает данные к аккаунтам
Google и требует отдельного упоминания в политике приватности. При нашем трафике
демография ничего не решает, а обязательства добавляет.

# Часть 2. Search Console

Сейчас не заведён вообще.

## Шаг 7. Завести property

https://search.google.com/search-console/welcome

Выбрать **левую** колонку — **Domain**. Ввести `notix-ai.app` без протокола и
без www.

**Почему Domain, а не URL prefix.** Domain покрывает http, https, www и все
поддомены одной записью. URL prefix покрывает ровно одну комбинацию, и что
половина данных уходит в незаведённый вариант, обнаруживается сильно позже.

Google выдаст строку вида `google-site-verification=...`.

**Добавить её в Cloudflare:**

https://dash.cloudflare.com/ → домен `notix-ai.app` → DNS → Records → **Add record**

| Поле | Значение |
|---|---|
| Type | `TXT` |
| Name | `@` |
| Content | строка от Google целиком |
| TTL | Auto |

Save, вернуться в Search Console, нажать **Verify**.

**Ожидается:** «Ownership verified» за несколько минут. Если не прошло — подождать
и нажать Verify ещё раз, DNS расходится не мгновенно.

**Важно:** запись потом **не удалять**. Google перепроверяет её периодически, и
при пропаже доступ отзывается.

---

## Шаг 8. Отправить sitemap

Search Console → левое меню → **Sitemaps** → в поле ввести `sitemap-index.xml` →
Submit

Полный адрес `https://notix-ai.app/sitemap-index.xml` — он уже отдаётся и уже
прописан в `robots.txt`.

**Ожидается:** статус **Success** и ненулевое число обнаруженных страниц. Обработка
занимает от часа до суток.

---

## Шаг 9. Проверить индексацию

Search Console → строка **URL inspection** вверху. Проверить по одному:

- `https://notix-ai.app/`
- `https://notix-ai.app/support/`
- `https://notix-ai.app/privacy/`
- `https://notix-ai.app/examples/`

**Ожидается:** «URL is on Google», либо «URL is not on Google» с кнопкой Request
Indexing — для нового сайта это нормально, просто запросите индексацию.

**Тревожный результат:** «Blocked by robots.txt» или «Excluded by noindex». Это
дефект в коде, а не настройка в панели — скажите мне, починю.

Раздел `/examples/` пока пуст. Вернуться к нему после публикации первых примеров
и тогда же запросить индексацию для нескольких страниц вручную.

---

## Шаг 10. Связать GA4 и Search Console

Только после того, как шаг 7 прошёл.

**10а.** GA4 админка → `Product links` → **Search Console links** → Link →
выбрать property → выбрать веб-поток → Submit

**10б.** GA4 → Reports → **Library** → карточка коллекции **Search Console** → ⋮ →
**Publish**

**Зачем второй шаг.** После связывания отчёт существует, но в меню его нет, пока
коллекция не опубликована. Ровно здесь обычно и решают, что связка не сработала.

**Ожидается:** в левом меню Reports появляется раздел Search Console с запросами.
Данные подтягиваются в течение суток.

# Что важно понимать про цифры

События уходят **только после нажатия Accept**. Отказавшиеся и закрывшие вкладку
до выбора в GA4 не попадают вообще — это цена выбранной схемы согласия, не
ошибка.

Реальный трафик выше того, что показывает GA4, и насколько — из GA4 не узнать.
Абсолютную посещаемость смотреть в аналитике Cloudflare: она серверная и согласия
не требует. GA4 использовать для сравнения источников и поведения — там смещение
одинаково по всем строкам и сравнению не мешает.

# Что решено не делать

**Consent Mode v2.** Текущая схема «не грузим ничего до согласия» проще и
юридически чище. Consent Mode слал бы обезличенные пинги от отказавшихся и
достраивал конверсии моделью — при нашем трафике модели не на чем учиться.

**Отдельное событие на просмотр примера.** `page_view` собирается и так.

**Событие на клик по ссылке источника.** Любопытно, но действий на основании
этого мы не предпримем. Понадобится — это два атрибута на ссылке, `analytics.js`
менять не придётся.

**Настройка аналитики приложения** (`530303000`). Отдельная задача, к сайту
отношения не имеет.

# Требуется ли что-то от меня в коде

Нет — при условии, что верификация GSC пройдёт через DNS. Если Google почему-то
предложит только вариант с HTML-тегом, скажите: мета-тег добавляется в
`src/layouts/Base.astro`, одна строка.
